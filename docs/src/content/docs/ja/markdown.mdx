Holloは表や`~~取り消し線~~`を含むMarkdown投稿に対応しています。
インスタンスの管理者は[`MARKDOWN_EXTENSIONS`][設定]で構文を追加できます。
拡張はローカル投稿の作成時と明示的な編集時に適用されます。
プロフィールの自己紹介やフィールドは従来のMarkdown構文を使います。

[設定]: /ja/install/env/#markdown_extensions-


拡張を有効にする
----------------

*.env*に使いたい拡張を設定し、Holloを再起動してください。

~~~~ bash
MARKDOWN_EXTENSIONS=footnote,ruby,math
~~~~

指定できる名前は`footnote`、`deflist`、`sub`、`sup`、`mark`、`ruby`、
`ins`、`abbr`、`tasklist`、`math`です。未設定または空ならすべて無効です。
名前の前後の空白と重複は無視され、不明な名前があると起動に失敗します。

設定を変えても保存済みのソースやHTMLは変わらず、既存の投稿の更新を送信しません。
明示的に編集すると現在の設定で描画し直します。拡張を無効にしてから古い投稿を
編集すると、元の構文が文字として現れる場合があります。


構文
----

| 拡張       | ソース                                | 意味                         |
| ---------- | ------------------------------------- | ---------------------------- |
| `footnote` | `本文[^1]`と`[^1]: 脚注`              | 番号付き脚注                 |
| `deflist`  | 用語の次の行に`: 定義`                | 定義リスト                   |
| `sub`      | `H~2~O`                               | 下付き文字                   |
| `sup`      | `x^2^`                                | 上付き文字                   |
| `mark`     | `==強調箇所==`                        | ハイライト                   |
| `ruby`     | `{漢字:かんじ}`                       | ルビ                         |
| `ins`      | `++追加した内容++`                    | 挿入した内容                 |
| `abbr`     | `*[HTML]: Hyper Text Markup Language` | 略語の定義                   |
| `tasklist` | `- [x] 完了`と`- [ ] 未完了`          | 静的なタスク状態             |
| `math`     | `$x^2$`と`$$x^2$$`                    | インライン数式と別行立て数式 |

対応する拡張を有効にすると、次のように書けます。

~~~~ markdown
ある主張[^1]。HTML は要素を持ちます。

[^1]: 補足説明。

用語
: 定義

*[HTML]: Hyper Text Markup Language

- [x] 執筆
- [ ] 確認
~~~~

脚注には実際の番号と元の投稿への絶対リンクが付きます。
定義リストには用語と説明を区切る句読点が含まれます。
ルビにはタグが除去される場合に備えた括弧が付きます。
Gukhanmunは明示的なルビを保護し、読みを重ねて追加しません。

略語は大文字・小文字と単語の境界を区別します。`HTML5`、`html`、`HTML은`は
`HTML`に一致しません。通常の文章で最初に一致した略語には、
「HTML (Hyper Text Markup Language)」のように展開した説明が表示されます。
リンクのラベル、URL、メンション、ハッシュタグ、コード、数式は対象外です。
重複する定義は最初のものを使い、説明は通常のテキストとして扱います。

タスク状態はクリックできるチェックボックスではなく、実際の`[x]`または`[ ]`の
文字として残ります。`[X]`も完了として認識します。印の後には空白か行末が
必要です。状態は投稿を編集して変えます。
`- [x]: note`のような行は、タスクではなくMarkdownのリンク定義になる場合があります。


エスケープと紛らわしい表記
--------------------------

構文をそのまま書くには、コードスパンを使うか区切り文字の前にバックスラッシュを
付けてください。`sup`や`sub`が有効な場合、顔文字や範囲に含まれる対の
キャレットやチルダが書式になることがあります。`\^_\^`や`1\~2,3\~4`と書くと
表記を保てます。添字内の空白は`x^a\ b^`のようにエスケープしてください。
従来の`~~取り消し線~~`も引き続き使えます。

`footnote`が有効なら`^[note]`はインライン脚注で、`sup`が有効なら
`^[note]^`は上付き文字です。受信側で添字が通常の文字列になる場合があるため、
重要な指数は「xのa+b乗」のように通常の文章でも説明してください。


数式
----

インラインの`$...$`は改行をまたげません。開始の`$`の直後と終了の`$`の直前には
空白を置けず、終了の`$`の直後には数字を置けません。
そのため`$5`や`$20 and $30`は通常の通貨表記として残ります。
ドル記号自体は`\$`でエスケープするか、コードスパン内に書いてください。

別行立て数式は行頭の`$$`で始めます。字下げは可能です。
終了の`$$`の後には、その行では空白だけを置けます。
`$$x^2$$`のように1行にも書けますが、文の途中の別行立て数式には対応していません。

~~~~ markdown
インライン数式は$x^2$です。

$$
\frac{a}{b}
$$
~~~~

数式は[FEP-dc88]で説明される方式に沿って、MathMLとTeX注釈を使います。
不正な式、安全でないコマンド、描画上限に達した式は、エスケープしたソースを
表示します。式ごとに独立したマクロ状態を持ち、展開回数と大きさを制限します。

上限は1式あたり8,192 UTF-16コード単位、1投稿あたり64式、1式の出力256 KiB、
数式出力の合計1 MiBです。投稿のソースが65,536 UTF-16コード単位を超えると、
数式の解析だけが無効になります。通常のMarkdownやメンション、ハッシュタグ、
リンクの処理は続きます。この場合、ドル記号で囲まれたテキストも保護された数式ではなく、
通常のMarkdown規則で解釈されます。

[FEP-dc88]: https://w3id.org/fep/dc88


他のサーバーで読む
------------------

受信側のサーバーやクライアントは書式を除去する場合があります。添字、ハイライト、
挿入の印、略語のツールチップが失われる可能性があります。
重要な訂正や定義は本文にも明記してください。
MastodonやMisskeyのルビ対応は内容や受信側のバージョンによります。

Mastodonは数式の注釈をドル記号付きのTeX文字列として表示できる場合がありますが、
数式の組版を保証するものではありません。Misskeyでは数式の表示テキストと
TeX注釈が連結される場合があります。表示はサーバーやクライアントによって
異なります。数式が重要な意味を持つ場合は、通常の言葉でも説明を添えてください。

実際のサーバー間[受け入れテスト]ではMastodon 4.7.3とMisskey 2026.10.0で
全10種類の例の受信を確認しました。Mastodonは編集を反映しましたが、
Misskey 2026.10.0はNoteの更新を無視し、元の内容を保持しました。
記録には受信したHTML/MFMと失われた情報が含まれます。
ブラウザー、クライアント、アクセシビリティの確認は未完了です。
